# Documentation Conventions

This file defines the rules and templates for all documentation under `docs/`.
It is the single source of truth for documentation structure. Generated files
(`INDEX.md`, `CAPABILITY_MATRIX.md`) are produced by scripts and must not be
edited by hand.

---

## 1. Directory Layout

```
docs/
├── INDEX.md                     # AUTO-GENERATED by scripts/gen-index.py
├── DOC_CONVENTIONS.md           # This file (template + rules)
├── CAPABILITY_MATRIX.md         # AUTO-GENERATED by scripts/gen-capability-matrix.py
├── language/
│   └── README.md                # Links to repo-root specs/*.md
├── architecture/
│   └── README.md                # High-level system overview
├── decisions/
│   └── README.md                # ADR index + numbering convention
└── omnisys/
    ├── README.md                # Parent overview + dependency map
    └── <module>/README.md       # One per OMNISYS module (see §3)
```

---

## 2. Header Requirements

### 2.1 Generated Files

Files marked `AUTO-GENERATED` MUST start with the following banner:

```markdown
<!-- AUTO-GENERATED by scripts/<name>.py — do not edit. Regenerate with: python scripts/<name>.py -->
```

### 2.2 Top-Level READMEs

`docs/language/README.md`, `docs/architecture/README.md`,
`docs/omnisys/README.md`, and `docs/decisions/README.md` are hand-written.

---

## 3. The OMNISYS Module README Template

Every `docs/omnisys/<module>/README.md` MUST contain exactly the following six
fields, in this order. **All six fields are required** — omitting any of them
is a verification failure.

### 3.1 Required Header Set

| # | Field | Requirement |
|---|-------|-------------|
| 1 | **Purpose** | Module mission statement |
| 2 | **Public API surface** | Pseudo-code type/signature blocks |
| 3 | **Dependencies** | Other OMNISYS or language subsystems relied upon |
| 4 | **Effects/capabilities used** | Explicit capability annotations (e.g. `uses network`) |
| 5 | **Status** | Exactly one of: `stable`, `experimental`, `planned` |
| 6 | **Open Questions** | Active trade-offs / unresolved design |

### 3.2 Template

```markdown
# OMNISYS.<module>

## Purpose

<one-to-three sentence mission statement>

## Public API surface

```omni
<type signatures and interface constructs>
```

## Dependencies

- <dependency 1>
- <dependency 2>

## Effects/capabilities used

- <capability annotation 1>
- <capability annotation 2>

## Status

<stable | experimental | planned>

## Open Questions

- <question 1>
- <question 2>
```

### 3.3 Machine-Readable Capabilities Line

Each module README MUST include a single `<!-- CAPABILITIES: ... -->` comment
listing the capability tags on one line. It is consumed by
`scripts/gen-capability-matrix.py`. Example:

```markdown
<!-- CAPABILITIES: network; database -->
```

---

## 4. Rules

1. **Link to specs/, do not restate.** Module docs reference the authoritative
   specification in the repo-root `specs/` (or `OMNI_SPEC.md`) rather than
   duplicating its content.
2. **Status values** are restricted to `stable`, `experimental`, `planned`.
   No other values are permitted.
3. **Link format.** All internal links use relative paths resolved from the
   file's own directory.
4. **Every file under `docs/`** MUST be referenced from `INDEX.md` (no orphans).
5. **Every OMNISYS module** in the §17.1 module tree MUST have a matching
   `docs/omnisys/<module>/README.md`.
